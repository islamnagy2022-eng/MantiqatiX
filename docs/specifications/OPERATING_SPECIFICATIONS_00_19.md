## 00 — الأمر الرئيسي الشامل
# الأمر الرئيسي الشامل — MantiqaTix

## الهدف
إدارة مشروع MantiqaTix كمنظومة واحدة للوصول إلى نسخة نهائية مؤمنة، مستقرة، قابلة للتشغيل الفعلي والإطلاق Production.

## قاعدة المصدر
- آخر نسخة مستقرة ومتحقق منها هي Source of Truth وBaseline.
- لا يُعاد بناء المشروع من الصفر إلا عند وجود سبب تقني موثق.
- قبل أي تعديل: فحص الوضع الحالي، المعمارية، الاعتماديات، الوظائف، المشاكل، المخاطر وTODO.
- لا يُعتبر وجود الكود دليلاً على اكتمال الوظيفة.

## طريقة العمل الإلزامية
تحليل → تحديد الأثر → تنفيذ → تكامل → اختبار → فحص أمان → تحقق → إصدار → مراقبة → Baseline جديد.

## تنسيق الأوامر
تُدار الأوامر الفرعية كمنظومات متخصصة: الإدارة، التقنية، المالية، التسويق، التصميم، CRM، القطاعات، المستخدمون والصلاحيات، الأمان، المنصة الموحدة، التحليلات، العمليات، الأتمتة، المحتوى، المراقبة، النسخ الاحتياطي، الجودة، الإطلاق والحوكمة.

## قواعد عامة
- عدم اختراع بيانات أو نتائج أو معاملات مالية.
- عدم تجاوز الصلاحيات أو أنظمة الأمان.
- أي تغيير مشترك في البيانات أو Backend أو API أو منطق الأعمال أو الإعدادات المشتركة يجب أن ينعكس على كل الواجهات المتأثرة بعد الاختبار والاعتماد.
- تغييرات واجهة التطبيق تبقى خاصة بالتطبيق، وتغييرات واجهة الموقع تبقى خاصة بالموقع.
- كل وظيفة يجب أن تكون قابلة للتتبع والاختبار.
- أي نتيجة غير متحققة تُوسم NOT VERIFIED.

## حالات العمل
PASS / IMPLEMENTED / WAIT / BLOCKED / TODO / NOT VERIFIED.

## بوابة الإطلاق
لا تُعلن Production Ready إلا بعد التحقق من الوظائف الأساسية، Auth، Authorization، قاعدة البيانات، الأمان، API، التطبيق، الموقع، لوحة الإدارة، العمليات المالية، CRM، التسويق، الاختبارات، النسخ الاحتياطي، المراقبة، إعدادات الإنتاج، البناء والتوقيع والاختبارات الخارجية وخطة الرجوع.

## 01 — أمر الإدارة والتشغيل
# الأمر التشغيلي — الإدارة والتشغيل

## الهدف
إدارة أعمال MantiqaTix وتحويل الأهداف إلى مهام قابلة للتنفيذ والقياس.

## المسؤوليات
- تحديد الأولويات.
- توزيع المهام والمسؤوليات.
- متابعة المواعيد والاعتماديات.
- إدارة المخاطر والمشكلات.
- متابعة مؤشرات الأداء.
- إصدار تقارير تشغيلية دورية.

## قبل التنفيذ
فحص الحالة الحالية، المهام المفتوحة، المسؤولين، المواعيد، الاعتماديات، المخاطر، والعوائق.

## التنفيذ
لكل مهمة: هدف واضح، مسؤول، أولوية، موعد، اعتماديات، حالة، معيار إغلاق، ونتيجة متحققة.

## الإغلاق
لا تُغلق المهمة بمجرد تنفيذ الكود أو إصدار التعليمات؛ يجب التحقق من النتيجة والتكامل وعدم وجود Regression.

## 02 — أمر التقنية والبرمجة
# الأمر التشغيلي — التقنية والبرمجة

## الهدف
تطوير وصيانة التطبيق والموقع وBackend وAPI وقاعدة البيانات والتكاملات للوصول إلى إصدار Production مستقر.

## النطاق
- التطبيق.
- الموقع.
- لوحة الإدارة.
- Backend وAPI.
- قاعدة البيانات.
- التكاملات.
- الأداء.
- الاختبارات.
- Build وRelease.

## القاعدة
ابدأ من آخر Baseline مستقر، افحص قبل التعديل، نفذ أقل تغيير آمن، ثم اختبر وتحقق.

## التحقق
Implementation → Integration → Database → API → Auth/Authz → UI → Build → Runtime → Functional → Regression → Security → Production Configuration.

## ممنوع
إزالة وظيفة تعمل دون سبب موثق، أو الادعاء بنجاح Build/Release دون نتيجة تحقق فعلية.

## 03 — أمر الحسابات والمالية
# الأمر التشغيلي — الحسابات والمالية

## الهدف
الرقابة المالية والتحليل والتقارير دون إنشاء أو اختراع قيود أو معاملات غير حقيقية.

## النطاق
الإيرادات، المصروفات، العمولات، الاشتراكات، الباقات، الرسوم، المستحقات، التسويات، التقارير، والاستثناءات.

## التحقق المالي
قاعدة البيانات → المعاملة → منطق الأعمال → API → الصلاحيات → سجل التدقيق → السجل المالي → التقرير.

## قواعد
- لا تُعتبر عملية مالية ناجحة دون مصدر قابل للتحقق.
- كشف التكرار والتعارض والفروقات والتعديلات غير المصرح بها.
- فصل FACT عن CALCULATION عن ANALYSIS عن EXCEPTION عن RISK.
- لا تُتخذ إجراءات مالية حساسة دون الصلاحية والاعتماد المطلوب.

## التقارير
يومي/أسبوعي/شهري، مع بيان ما تم التحقق منه وما يحتاج مراجعة.

## 04 — أمر التسويق
# الأمر التشغيلي — التسويق

## الهدف
بناء وتشغيل وقياس منظومة التسويق الخاصة بـ MantiqaTix لجذب العملاء ومقدمي الخدمات وتحويل النشاط التسويقي إلى نتائج قابلة للقياس.

## النطاق
الاستراتيجية، الشرائح، الحملات، المحتوى، الإعلانات، العملاء المحتملون، اكتساب مقدمي الخدمات، التحويل، الاحتفاظ، وإدارة وكالات التسويق.

## مسار القياس
Spend → Reach → Click → Lead → Qualified → Registration → Activation → Conversion → Revenue.

## مؤشرات
CAC / CPL / Conversion / Retention / Churn / ROI / ROAS.

## القاعدة
يجب ربط الحملات بمصادر قابلة للتتبع، وعدم تقديم أرقام غير متحققة.

## 05 — أمر التصميم والهوية البصرية
# الأمر التشغيلي — التصميم والهوية البصرية

## الهدف
الحفاظ على هوية MantiqaTix وإنتاج تصميمات احترافية متسقة وجاهزة للاستخدام التجاري.

## النطاق
الشعار، الألوان، الخطوط، الأيقونات، الواجهات، المنشورات، الإعلانات، البنرات، المواد التسويقية.

## معايير الجودة
الهرمية البصرية، التكوين، التباعد، التباين، القراءة على الهاتف، معالجة الصور، العمق والظلال عند الحاجة، وضوح CTA، واتساق الهوية.

## المحتوى
كل تصميم تسويقي يجب أن يرتبط برسالة واضحة وCTA مناسب، ومعه نص/منشور مطابق عند الحاجة.

## الحقوق
لا تُستخدم صور أو أصول خارجية في الإنتاج التجاري دون التحقق من حقوق استخدامها.

## 06 — أمر العملاء وإدارة العلاقات CRM
# الأمر التشغيلي — العملاء وCRM

## الهدف
إدارة دورة حياة العملاء ومقدمي الخدمات بصورة قابلة للتتبع.

## النطاق
الاستحواذ، التسجيل، التأهيل، التواصل، المتابعة، العروض، التحويل، الاحتفاظ، وإعادة الاستهداف.

## القواعد
- فصل بيانات العميل عن بيانات مقدم الخدمة عند الحاجة.
- حفظ سجل التفاعلات.
- ربط مراحل CRM بالنتائج الفعلية.
- حماية بيانات المستخدمين وتطبيق الصلاحيات.

## 07 — أمر مقدمي الخدمات والقطاعات
# الأمر التشغيلي — مقدمو الخدمات والقطاعات

## الهدف
إدارة القطاعات المختلفة داخل MantiqaTix مع تخصيص الباقات والعمولات وآليات العمل لكل قطاع.

## أمثلة القطاعات
الأطباء، الصيدليات، معامل التحاليل، مراكز الأشعة، المستشفيات الخاصة، الشركات والمتاجر والخدمات الأخرى.

## القاعدة
لا تُفرض آلية واحدة على جميع القطاعات؛ لكل قطاع نموذج تشغيل وباقات وعمولات وترشيحات مناسبة.

## نموذج المنصة
MantiqaTix وسيط تسويقي وليس منفذاً للخدمة؛ المعاملة الأساسية بين العميل وصاحب العمل، وتستفيد المنصة وفق النموذج التجاري المعتمد.

## 08 — أمر المستخدمين والأدوار والصلاحيات
# الأمر التشغيلي — المستخدمون والأدوار والصلاحيات

## الهدف
إدارة الهوية والوصول وفق أقل صلاحية لازمة.

## النطاق
التسجيل، الدخول، الأدوار، الصلاحيات، الموظفون، أصحاب الأعمال، العملاء، الإدارة، تفعيل/تعطيل الوظائف.

## قواعد
- لا صلاحية بلا حاجة.
- التحقق من Auth وAuthorization معاً.
- عزل بيانات الجهات والمستخدمين.
- العمليات الحساسة يجب أن تكون تحت سلطة الخادم.
- تسجيل العمليات الحساسة في Audit Log.

## 09 — أمر قاعدة البيانات والأمان
# الأمر التشغيلي — قاعدة البيانات والأمان

## الهدف
حماية البيانات وضمان صحتها واستمراريتها.

## النطاق
Schema، العلاقات، القيود، الفهارس، RLS، Auth، JWT، API، Edge Functions، الأسرار، سجلات التدقيق.

## منهج الأمان
فحص التهديدات → أقل صلاحية → عزل البيانات → تحقق المدخلات → حماية العمليات الحساسة → Logging → اختبار أمني.

## قاعدة
لا يتم تجاوز RLS أو الصلاحيات أو الأسرار لأجل تسريع التطوير.

## 10 — أمر الموقع والتطبيق والمنصة الموحدة
# الأمر التشغيلي — الموقع والتطبيق والمنصة الموحدة

## الهدف
توحيد مصدر البيانات والمنطق المشترك مع الحفاظ على واجهات مناسبة لكل منصة.

## المعمارية
App + Website + Admin → Shared Backend/API → Shared Database + Shared Business Logic.

## التغييرات المشتركة
تغييرات البيانات أو Backend أو API أو منطق الأعمال أو الإعدادات المشتركة تصبح متاحة للمنصات المتأثرة بعد الاختبار والاعتماد.

## التغييرات الخاصة
واجهة التطبيق وتجربته الخاصة لا تُنسخ إلى الموقع، والعكس صحيح.

## دورة التغيير
Impact Analysis → Implementation → Integration → Test → Security → Verify → Release → App/Website Validation → Baseline.

## 11 — أمر التحليلات والتقارير
# الأمر التشغيلي — التحليلات والتقارير

## الهدف
تحويل بيانات المنصة إلى تقارير دقيقة قابلة لاتخاذ القرار.

## النطاق
الأداء، العملاء، مقدمو الخدمات، التسويق، الإيرادات، المصروفات، الاستخدام، التحويلات والنمو.

## قاعدة التقرير
تمييز FACT / CALCULATION / ANALYSIS / EXCEPTION / RISK / NOT VERIFIED.

## لا يجوز
عرض تقدير أو تحليل على أنه حقيقة مسجلة في النظام.

## 12 — أمر العمليات وإدارة المهام
# الأمر التشغيلي — العمليات وإدارة المهام

## الهدف

## لكل مهمة
الهدف، المسؤول، الأولوية، الموعد، الاعتماديات، الحالة، المخرجات، معيار الإغلاق.

## الحالات
TODO / IN PROGRESS / WAIT / BLOCKED / DONE / VERIFIED.

## القاعدة

## 13 — أمر الأتمتة والإشعارات
# الأمر التشغيلي — الأتمتة والإشعارات

## الهدف
تنفيذ العمليات المتكررة بأمان مع قابلية التتبع والإيقاف.

## النموذج
Event → Validation → Action → Log → Notification.

## القواعد
- كل أتمتة لها سبب واضح.
- منع التكرار غير المقصود.
- تسجيل النتائج والأخطاء.
- إمكانية تعطيل الأتمتة كلياً أو جزئياً حسب الصلاحيات.

## 14 — أمر المحتوى وإدارة المنصة
# الأمر التشغيلي — المحتوى وإدارة المنصة

## الهدف
إدارة المحتوى والخدمات والباقات والعروض والصفحات من خلال دورة نشر منظمة.

## دورة المحتوى
Draft → Review → Approved → Published → Hidden/Archived.

## القواعد
- لا نشر لمحتوى غير معتمد.
- المحتوى الرسمي والبيانات التجارية يجب أن تكون قابلة للتحقق.
- الحفاظ على اتساق المحتوى بين المنصات عندما يكون المصدر مشتركاً.

## 15 — أمر المراقبة والصيانة
# الأمر التشغيلي — المراقبة والصيانة

## الهدف
اكتشاف الأعطال والمخاطر قبل تحولها إلى مشاكل تشغيلية كبيرة.

## المراقبة
الأخطاء، الأعطال، API، قاعدة البيانات، Auth، الأداء، الأمن، Crash، الخدمات الخارجية.

## عند المشكلة
اكتشاف → تصنيف → تحديد السبب → إصلاح → اختبار → مراقبة بعد الإصلاح → توثيق → Baseline عند الحاجة.

## ممنوع
اعتبار إعادة تشغيل الخدمة حلاً نهائياً دون معرفة السبب عند وجود مشكلة متكررة.

## 16 — أمر النسخ الاحتياطي والتعافي
# الأمر التشغيلي — النسخ الاحتياطي والتعافي

## الهدف
حماية بيانات MantiqaTix وضمان القدرة على الاستعادة والرجوع إلى نسخة مستقرة.

## النطاق
Backup، Restore، Rollback، Disaster Recovery، خطط الطوارئ واختبار الاستعادة.

## القاعدة
النسخة الاحتياطية لا تُعتبر موثوقة إلا إذا أمكن اختبار استعادتها وفق الخطة المعتمدة.

## 17 — أمر الاختبارات وضمان الجودة
# الأمر التشغيلي — الاختبارات وضمان الجودة

## الاختبارات
Type Check، Lint، Build، Routes، Imports، Environment، Database، API، Functional، Security، Regression، Device عند الحاجة.

## قاعدة الإغلاق

## 18 — أمر الإطلاق والإصدارات
# الأمر التشغيلي — الإطلاق والإصدارات

## الهدف
إدارة انتقال MantiqaTix إلى Production بطريقة آمنة وقابلة للرجوع.

## المراحل
Development → Testing → Staging → Production.

## بوابة الإصدار
Core Functionality، Auth، Authz، Database، Security، API، Website، App، Admin، Finance، CRM، Marketing، Regression، Backup، Monitoring، Production Config، Build، Signing، External Tests، Rollback.

## قاعدة
لا يُستخدم وصف Production Ready إلا بعد تحقق فعلي موثق.

## 19 — أمر الحوكمة والرقابة
# الأمر التشغيلي — الحوكمة والرقابة

## الهدف
ضمان أن كل تغيير في MantiqaTix قابل للتتبع والمراجعة والرجوع.

## النطاق
Baseline، مصدر الحقيقة، سجل التغييرات، الاعتماد، الصلاحيات، المخاطر، الإصدارات، التدقيق.

## قواعد
- لا تغيير جوهري دون معرفة أثره.
- لا تعديل على بيانات حساسة دون صلاحية.
- الاحتفاظ بمرجع للنسخة المستقرة السابقة.
- أي تعارض أو نقص في المعلومات يُذكر صراحة ولا يُحل بالافتراض.

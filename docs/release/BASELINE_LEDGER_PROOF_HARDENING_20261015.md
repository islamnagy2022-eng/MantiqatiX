## Finding

`scripts/validate-production-schema-baseline.mjs --verify` validates the migration-ledger list against the manifest only when the external file selected by `BASELINE_LEDGER_VERSIONS_FILE` (default `/tmp/mantiqatix-ledger-versions.txt`) exists. In the reviewed replay workflow, that live-ledger export is not produced; the workflow instead checks out the baseline PR. Consequently, the baseline-forward replay path does not independently compare the recorded migration count/hash/checkpoint to a separate ledger-version export at replay time.

The validator still checks the snapshot SHA-256 against the manifest and validates the manifest's declared checkpoint/count/hash formats. These checks do not by themselves independently establish that the declared ledger list is the exact list observed during capture.

## Required remediation

1. Extend the capture manifest with the full ordered, unique, 14-digit `applied_migration_versions` array from the read-only ledger export.
2. During capture, verify the array is strictly ascending, unique, has the declared count, ends at `last_applied_migration_version`, and hashes to `applied_migration_versions_sha256`.
3. During `--verify`, require that embedded array and revalidate all those invariants. If an external ledger export is supplied, compare the entire list and hash exactly.
4. Add tests for missing embedded ledger evidence, invalid version, duplicate/out-of-order entries, wrong checkpoint, wrong count, wrong hash, and disagreement with an external export.
5. Keep the current PR #249 manifest unapproved until the snapshot is reviewed and the manifest is regenerated by the hardened capture workflow. Do not manually invent the ledger list.
6. Bind the replay workflow to the exact reviewed baseline commit SHA and confirm its manifest and snapshot hashes before the local disposable stack starts.
7. After the changes, run validator tests and a full isolated forward replay on the exact final commit; preserve the run URL and artifact.

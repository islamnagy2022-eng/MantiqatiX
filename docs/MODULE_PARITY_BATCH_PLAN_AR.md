# MantiqatiX — خطة رفع الموديولات المشابهة للمطاعم إلى نفس المرحلة

التاريخ: 2026-10-23
فرع العمل: work/module-parity-wave1-20261023
الهدف: رفع الموديولات ذات أنماط CRUD والطلبات والكتالوج إلى مستوى تنفيذ المطاعم الحالي، دون الادعاء بأن أي موديول جاهز للإطلاق قبل إثبات الاختبارات.

## تعريف «نفس مرحلة المطاعم الحالية»
هذه مرحلة تطوير مرشحة وليست اعتماد إنتاج:
- واجهة تشغيل عربية RTL متكاملة للحالات الأساسية.
- تحميل حقيقي من المصادر المعتمدة فقط، مع حالات loading / empty / error / permission-denied وإعادة المحاولة.
- نطاق المؤسسة/النشاط/الفرع/المستخدم واضح ومطبق في الاستعلامات، مع fail-closed عند غياب العضوية أو غموضها.
- RBAC مركزي، وعدم اعتبار إخفاء الزر تفويضًا.
- الكتابات الحساسة عبر RPC/Edge Function معتمدة؛ لا direct writes جديدة إلى بيانات مالية أو مخزون أو حالات طلب.
- بحث وفلاتر وتفاصيل سجل وحالات دورة حياة واضحة، دون بيانات أو أرقام وهمية.
- validators لعقود المصدر واختبارات JavaScript syntax وCI على نفس commit.
- قائمة نواقص واختبارات E2E متعددة الأدوار موثقة. هذا المستوى لا يساوي DEPLOYED أو VERIFIED أو GO-LIVE.

## موجة التنفيذ الأولى — الترتيب
1. مقدمو الخدمات والأنشطة والفروع (C4): الملف والخدمات والأسعار والمناطق والتوفر وساعات العمل؛ أساس مشترك لقطاعات متعددة.
2. الطلبات والعمليات والحجوزات (C3): قائمة الطلبات، التفاصيل، البحث والفلاتر، إجراءات الحالة عبر المسار الخادمي، عزل العميل/المزود/النشاط.
3. التجارة والأزياء والبقالة والسوبر ماركت (C9): كتالوج مركزي، خيارات/مقاسات، الأسعار والتوفر، سلة متعددة العناصر، طلبات؛ المخزون يظل قراءة فقط إلى أن يتوفر مسار حركة خادمي موثوق.
4. الصيانة والخدمات المهنية والقانونية (C12): طلب/عرض/قبول/تعيين/إنجاز؛ إخفاء الوثائق والبيانات الحساسة عن غير المخولين.
5. المستخدمون وCRM والدعم (C7): العملاء المحتملون والمتابعة والتذاكر والرسائل مع فصل المؤسسات وتقييد التصدير.
6. التسويق والإعلان وشركات التسويق (C5): العملاء المحتملون والمشروعات والحملات والموافقات؛ لا إطلاق حملات مدفوعة ولا تكاملات خارجية دون اعتماد واضح.
7. التعليم والوظائف والمستعمل: استكمال الواجهات المشتركة مع مراجعة إضافية لخصوصية القاصرين والملفات الشخصية والعروض.

## نتيجة مراجعة المصدر — 2026-10-23
هذه نتائج قراءة ملفات main الحالية، وليست نتيجة تشغيل E2E:
- مقدمو الخدمات: يوجد عقد قائم على `marketing_provider_profiles` و`marketing_services` و`marketing_provider_services`. توثيق RC100 يذكر تضييق الكتابة إلى مالك الملف، وRC341 يذكر واجهة ملف عام مشروطة بنشاط ACTIVE و`settings.showcase=true`. يجب التأكد من أن الواجهة التشغيلية تغطي التعديل والخدمات والأسعار والتوفر والصلاحيات، واختبارها بحسابات متعددة.
- الطلبات: المطاعم تستخدم جدول `orders` المركزي مع `order-create` و`order-status-update`. المطلوب فحص ما إذا كانت بقية قطاعات الطلبات تستخدم نفس دورة الحياة أم لديها مسارات قديمة؛ لا ننشئ جدول طلبات بديلًا.
- السوبر ماركت والأزياء: `web/operations-modules.js` يعرّف وحدات على `catalog_items` و`catalog_item_prices` و`inventory_transactions` و`orders`، والأزياء على `fashion_products` و`fashion_orders` و`fashion_tailor_services`. تعريف المصادر وحده لا يثبت اكتمال عمليات السلة أو حركات المخزون أو الاسترجاع.
- CRM: سجل MASTER_PRODUCTION_TODO يوثق RC460 وPR #64 كتنفيذ وCI ناجحين، مع بقاء المتصفح وE2E متعدد المستخدمين غير متحققين. لا نعيد بناءه؛ نراجع فجوات التشغيل ونغطيها.
- الطبي: RC172 يوثق حجزًا خادميًا وصلاحيات RLS، لكنه يذكر صراحة أن browser E2E وعزل حجز مستخدمين والإشعارات والتسوية والمزامنة ما زالت مفتوحة. لا نضيف ملفات طبية أو تشخيصات غير موجودة في العقد.
- التسويق: يوجد PR #299 كمسودة تتضمن تغييرات حملات ودورة حياة الشركاء وقيودًا أمنية. لا ندمجه ولا نعتبر تغييرات migrations حية قبل مراجعة السلسلة وإثبات CI على الرأس الحالي.

## بوابة قبول موحدة لكل موديول
- [ ] فحص المصدر الحالي واعتمادياته ومصدر الحقيقة قبل تعديل الكود.
- [ ] تحديد الجداول/RPC/Edge Functions المتاحة فعليًا؛ لا اختراع schema أو endpoint.
- [ ] توحيد العضوية والنطاق مع عقد RBAC/RLS القائم.
- [ ] واجهة قائمة + بحث/فلترة + تفاصيل + حالات فارغة/خطأ/تحميل/منع صلاحية.
- [ ] تحقق من المدخلات ورسائل آمنة؛ لا نجاح قبل تأكيد الخادم.
- [ ] عدم إضافة كتابة مباشرة إلى الأسعار/الطلبات/المخزون/الأموال.
- [ ] اختبارات عقد regression لكل قيد أمني وسلوكي تمت إضافته.
- [ ] JavaScript syntax + validators + CI على رأس الفرع نفسه.
- [ ] توثيق اختبار E2E المطلوب وما لم يتم اختباره.
- [ ] لا دمج ولا نشر ولا تغيير إنتاج ضمن هذه الموجة دون تحقق وموافقة مستقلة.

## ضوابط مشتركة
- عدم إنشاء migrations أو تغيير RLS أو grants لمجرد تمرير الاختبارات.
- عدم إعادة بناء وحدة المطاعم أو نسخها عشوائيًا؛ استخراج الأنماط المشتركة بعد مراجعة المصدر.
- لا استخدام بيانات إنتاج حساسة في الاختبارات، ولا مدفوعات حقيقية.
- الموديول الطبي والزواج لا يُعاملان كمجرد CRUD عام بسبب البيانات الحساسة ومتطلبات الخصوصية.
- تبقى بوابة الإنتاج العامة BLOCKED ما دامت حواجز P0 في MASTER_PRODUCTION_TODO غير مغلقة.

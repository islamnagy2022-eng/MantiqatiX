# تشغيل بيئة MantiqatiX-DEMO المجانية

## الهدف

استخدام مشروع Supabase منفصل للتطوير المحلي دون تغيير مصدر بيانات الموقع المنشور. المشروع:

- الاسم: `MantiqatiX-DEMO`
- Project ref: `lkijdgqanbqjudiducjt`
- المؤسسة: `manteqti` — خطة Free
- الرابط: `https://lkijdgqanbqjudiducjt.supabase.co`

## الحالة التي تم التحقق منها في 2026-11-28

- المشروع `ACTIVE_HEALTHY`.
- قاعدة البيانات تحتوي على 132 جدولًا في `public`، وRLS مفعّل على جميعها.
- فحص عددي مباشر وجد مستخدم Auth واحدًا ومستأجرًا واحدًا؛ ولم يجد أي نشاط أو فرع أو عضوية أو منتج كتالوج. لا تُعرض هوية المستخدم في هذا التقرير.
- سجل الترحيلات يحتوي على 8 إصدارات Demo فقط.
- توجد 8 Edge Functions بأسماء `demo-*`.
- لم تُنقل بيانات الإنتاج إلى المشروع، ولم تُطبّق عليه ترحيلات المشروع الرئيسية.

## التوصيل المحلي

1. افتح Supabase Dashboard لمشروع `MantiqatiX-DEMO` ثم Project Settings → API Keys.
2. انسخ **Publishable key** الخاص بمشروع DEMO فقط. لا تستخدم `service_role` أو أي Secret Key.
3. من مجلد `apps/catalog-frontend` انسخ `.env.example` إلى `.env.development.local`.
4. استبدل قيمة `VITE_SUPABASE_PUBLISHABLE_KEY` بمفتاح DEMO الحقيقي.
5. شغّل:

```bash
npm ci
npm run dev:demo
```

يجب تشغيل Vite من `apps/catalog-frontend` باستخدام `npm run dev:demo`؛ المنفذ 8080 موجود ضمن عناوين CORS لوظائف Demo الحالية.

## حماية الإنتاج

- عند تشغيل `npm run dev` يرفض التطبيق أي عنوان غير عنوان DEMO المحدد، ويرفض الرجوع التلقائي إلى إعدادات الإنتاج.
- مفتاح المتصفح المقبول هو Publishable key فقط.
- جلسات تسجيل الدخول المحلية تستخدم `mantiqatix.demo.auth` المنفصلة عن جلسات الإنتاج.
- ملف `.env.development.local` مستثنى من Git، بينما `.env.example` يحتوي على عنوان المشروع وعنصر نائب للمفتاح فقط.
- بناء الإنتاج لا يستخدم متغيرات التطوير، ويظل `apps/catalog-frontend/public/config.js` مربوطًا بمشروع `MANTIQATIX FINAL`.
- لا تشغّل `supabase db push` ولا تطبّق ترحيلات على المشروع التجريبي قبل مراجعة سجل الترحيلات والفروقات البنيوية والتبعيات.

## حدود التكامل الحالية

وجود الجداول ووظائف `demo-*` لا يعني أن وظائف الإنتاج الحديثة متاحة في DEMO. واجهة الكتالوج الحالية تستدعي وظائف مثل `catalog-admin` و`catalog-platform-admin` و`public-catalog-directory` و`ai-gemini-proxy`، بينما الجرد الحالي أظهر وظائف Demo مخصصة فقط. يلزم تجهيز نسخة تطوير من الوظائف المطلوبة ومراجعة اعتمادها على RPCs والجداول والأسرار قبل اختبار تلك الشاشات.

مراجعة Supabase Advisor في 2026-11-28 أظهرت سياسات RLS مفعّلة دون سياسات على جدولين (وهو منع افتراضي للوصول)، وتحذيرات بشأن وظائف `SECURITY DEFINER` متاحة لبعض الأدوار، وتعطيل حماية كلمات المرور المسربة. كما ظهرت 106 ملاحظات فهارس لمفاتيح أجنبية. هذه نتائج مراجعة وليست تصريحًا بتعديل الصلاحيات؛ يجب فحص كل وظيفة وسياسة قبل فتح أي مسار اختبار حساس.

## قاعدة التشغيل

# RC347–RC349 — واجهة الأنشطة والهوية المرنة

## الهدف
استكمال واجهة العرض العامة للأنشطة والإعلانات مع تفاعل داخلي بدون تحويل عناصر العرض إلى روابط مرئية، وإضافة طبقة تغيير لوجو آمنة لا تستبدل الأصل.

## المنفذ

### 1. عرض الأنشطة والأيقونات
- استخدام أصول `assets/activities/` الرسمية للأنشطة المعروفة.
- الحفاظ على fallback القديم للقطاعات التي لا تملك أصلًا رسميًا.
- صور/أيقونات النشاط قابلة للنقر وتفتح الملف داخل تجربة المنصة.
- لا يتم تحويل بطاقة النشاط إلى `<a>` خارجي.
- الوصول بالكيبورد محفوظ للعناصر التفاعلية.

### 2. الإعلانات
- الإعلان الموجه لا يعرض `target_url` كرابط داخل البطاقة.
- الضغط على الإعلان يفتح نافذة داخلية.
- الرابط الخارجي، إن كان موجودًا، لا يظهر كنص للمستخدم؛ يظهر فقط كزر «فتح الإعلان» بعد فتح النافذة.
- الإعلانات غير المرتبطة بعنوان صالح لا تحصل على زر خارجي وهمي.

### 3. لوجو المنصة
- جدول `platform_brand_assets` يحتفظ بـ:
  - `asset_path`: النسخة الحالية.
  - `original_asset_path`: الأصل غير القابل للاستبدال من خلال الواجهة.
  - `version`: رقم النسخة.
- الأصل الحالي:
  - `assets/mantiqatix-logo.svg`
  - `assets/mantiqatix-mark.svg`
- التغيير يتم برفع ملف جديد إلى مسار مستقل داخل Storage.
- Super Admin فقط يستطيع تفعيل النسخة الجديدة.
- الرجوع للأصل يغيّر المرجع فقط ولا يحذف النسخ المرفوعة.

### 4. لوجو النشاط
- صورة النشاط الحالية `profile_image_path` لم تتغير.
- لوجو النشاط الجديد يحفظ منفصلًا في:
  `settings.branding.logo_path`
- مسار Storage مستقل:
  `users/{user}/providers/{provider}/logo.webp`
- يوجد في «ملف نشاطي»:
  - حفظ لوجو النشاط.
  - الرجوع للهوية الأصلية.
- تغيير اللوجو لا يغير الصورة الأصلية ولا الأيقونة الرسمية.

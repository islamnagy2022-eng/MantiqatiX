## تعريف الحالات

- `TODO`: لم ينفذ.
- `IN_PROGRESS`: قيد التنفيذ.
- `FIXED_PENDING_TESTS`: تم تعديل المصدر، ولم يثبت السلوك بعد.
- `BLOCKED_EXTERNAL`: يحتاج إعدادًا أو صلاحية أو جهازًا أو بيانات/بيئة غير متاحة.
- `VERIFIED_SOURCE`: اجتازت فحوص المصدر/البناء المحددة فقط.
- `VERIFIED_INTEGRATION`: اجتازت اختبار التكامل في بيئة معزولة.
- `RELEASE_READY`: اجتازت جميع معايير قبول الموديول ذات الصلة، مع بقاء اعتماد بوابة الإصدار العامة منفصلًا.

## P0 — ERP Receiving: مانع إغلاق متبقٍ

- [ ] **MOD-P0-10 — بنود أوامر الشراء وحدود الاستلام.** المخطط الحالي لـ `erp_purchase_orders` لا يحتوي جدول بنود شراء يربط كل أمر بالمنتجات والكميات المعتمدة. RC434 اجتاز اختبار PostgreSQL معزول للتكرار والرفض والتراجع الذري في [CI run 37874933289](https://github.com/islamnagy2022-eng/MantiqatiX/actions/runs/37874933289). يتحقق من نطاق المؤسسة والمستودع والمنتج ومن أن أمر الشراء معتمد، ويجعل الإيصال وتحديث المخزون ودفتر حركة المخزون عملية ذرية؛ لكنه لا يستطيع حتى الآن إثبات أن المنتج والكمية واردان ضمن بنود أمر الشراء أو منع تجاوز الكمية المطلوبة. لا تُعلن دورة ERP/المخزون مكتملة ولا تطلقها على أنها محاسبيًا مكتملة قبل إضافة بنود أمر الشراء وربطها بإنشاء الأمر والاستلام واختبار حد الكمية.

- [ ] **MOD-P0-11 — منع تكرار إنشاء نية دفع اشتراك عند غموض نتيجة Paymob.** RC435 يطالب بحجز نية الاشتراك إلى `PENDING` قبل الاتصال الخارجي، ويمنع إعادة الاتصال إذا كانت النية `PENDING` بلا provider correlation. أُضيف اختبار PostgreSQL معزول لحالة الحجز والتكرار والربط الجزئي والعزل. لا يُغلق البند قبل نجاح CI على آخر commit، واختبار Paymob sandbox، ومصالحة أي نوايا `CREATED/PENDING` قديمة قبل النشر. حالة المصدر: `INTEGRATION_VERIFIED / SANDBOX_BLOCKED`؛ اختبارات RC435 في PostgreSQL معزول وفحوص المصدر نجحت في [CI run 37874933289](https://github.com/islamnagy2022-eng/MantiqatiX/actions/runs/37874933289). ما زال اختبار Paymob sandbox ومراجعة استعادة checkout مطلوبين. لم يتم نشر الدالة أو تطبيق RC435 على الإنتاج.

- [ ] **MOD-P0-12 — ترحيل القيود المالية الذري.** كشف الفحص القراءة فقط أن RPC القديم الذي يستدعيه Edge Function لا يمنح `service_role` صلاحية التنفيذ، وأن مخطط الجداول يفتقد أعمدة يستخدمها عقد RPC القديم (`total_debit/total_credit/posted_at/entry_number/line_number`). أُضيف RC436 لمواءمة المخطط وإضافة RPC جديد يثبت توازن القيد ونطاق الحساب والمستأجر ويكتب الرأس والأسطر ودفتر الأستاذ في معاملة واحدة مع idempotency. حالة التنفيذ: `VERIFIED_INTEGRATION / RELEASE_BLOCKED`. اجتاز RC436 اختبار PostgreSQL المعزول في [CI run 37875484588](https://github.com/islamnagy2022-eng/MantiqatiX/actions/runs/37875484588)، بما في ذلك التكرار، التوازن، الصلاحيات، تضارب رقم القيد والتراجع الذري عند فشل دفتر الأستاذ. ما زالت مراجعة محاسبية مستقلة واختبار الترحيل على نسخة قاعدة مماثلة للإنتاج ومراجعة القيود التاريخية مطلوبة. لم يُطبق RC436 على الإنتاج.


- [ ] **MOD-P0-14 — بنود أوامر الشراء وحدود الاستلام RC437/RC438.** أُضيف جدول `erp_purchase_order_lines` بكمية مطلوبة ومستلمة تراكميًا؛ إنشاء أمر الشراء وبنوده صار في RPC واحد مرتبط بـ `auth.uid()`، مع حساب الإجمالي من البنود والتحقق من المؤسسة والفرع والدور وإعادة المحاولة الآمنة. الإرسال للاعتماد يتطلب وجود بنود، والاستلام يرفض المنتج غير المدرج أو تجاوز الكمية أو اختلاف تكلفة الوحدة، ويمنع replay من مضاعفة المخزون أو الكمية المستلمة. أضيفت اختبارات PostgreSQL معزولة في CI. الحالة لا تُرفع إلى `VERIFIED_INTEGRATION` إلا بعد نجاح أحدث CI؛ تظل بيانات أوامر الشراء القديمة بلا بنود مانعًا يتطلب مصالحة قبل الاستلام. لم يُطبق RC437/RC438 على الإنتاج.

- [ ] **MOD-P0-16 — تقوية search_path للدوال SECURITY DEFINER المكشوفة RC440.** فحص قراءة فقط للإنتاج وجد 22 دالة SECURITY DEFINER قابلة للاستدعاء من anon/authenticated بإعداد `search_path=public`. أُضيف ترحيل ديناميكي محدود النطاق يغيّر هذه الدوال فقط إلى `public, pg_temp`، مع اختبار يثبت أن الدوال الخاصة بـ service_role لا تتغير. الحالة: `FIXED_PENDING_TESTS` حتى نجاح CI ومراجعة أسماء الدوال المتأثرة في بيئة staging؛ لم يُطبق RC440 على الإنتاج.

- [ ] **MOD-P0-15 — استعادة Checkout بعد فقد الاستجابة RC439.** أُضيفت أعمدة مشفرة للسر مع IV عشوائي وإصدار مفتاح، وتشفير AES-256-GCM داخل Edge Function، واستعادة checkout الحالي عند إعادة الطلب بدل إنشاء نية جديدة. أضيف runbook لتوليد المفتاح وتدويره، واختبار تحقق للمخطط والعقد. لا يُغلق البند حتى نجاح CI على أحدث commit، وضبط سر التشفير في Supabase، واختبار Paymob sandbox يحاكي فقد الاستجابة. أي نية قديمة بلا سر مشفر تبقى للمصالحة ولا يعاد إنشاؤها تلقائيًا. لم يُطبق RC439 على الإنتاج ولم تُضبط أسرار الإنتاج.

- [ ] **MOD-P0-13 — المصالحة عند فشل حفظ ربط Paymob.** RC439 يعالج فقد استجابة العميل بعد حفظ provider IDs والسر المشفر؛ الحالة المتبقية هي قبول Paymob للنية ثم فشل حفظ provider IDs/ciphertext. يجب إثبات مصالحة آمنة باستخدام مرجع المزود وwebhook دون إنشاء نية بديلة أو تفعيل الاشتراك دون callback موثوق. لا تُغلق قبل اختبار sandbox لمحاكاة فشل DB بعد قبول المزود. حالة: `TODO`؛ مانع دفع قبل الإطلاق.

## الدفعة المنفذة أثناء هذه الجولة

**SMM / طلب الخدمة الخارجية — تعديل مصدر مبدئي:**
- أُضيف timeout محدد لطلب مزود الخدمة.
- أصبح انقطاع الشبكة/HTTP غير الحاسم/الرد غير القابل للتحليل حالة غامضة تتطلب المصالحة، ولا يؤدي إلى استرداد تلقائي.
- الاسترداد التلقائي مقصور على الرفض الصريح الذي يمكن تمييزه من استجابة المزود.
- إذا قبل المزود الطلب ثم فشل حفظ رقم طلبه محليًا، لا يجري استرداد تلقائي؛ يُسجل طلب المصالحة.
- أُضيف التحقق من رابط الهدف والمبلغ/السعر والكمية قبل الخصم.
- حُصر تفويض إدارة SMM في قائمة `smm_admins` الخلفية بدل اعتبار أي مالك/مدير مؤسسة مسؤولًا عن المنصة كلها. أصبحت الواجهة تسأل الخادم عن صلاحية الإدارة.
- حُميت حالات الطلب النهائية من الرجوع إلى `PROCESSING` بسبب رد مزود متأخر، وأصبح تحديث الحالة يتحقق من ملكية الطلب ويتأكد من حفظ التغيير.
- أُضيف عقد تحقق مصدر مستقل لهذا المسار.

- أضيف RC432 لمنع تكرار قيود الخصم/الاسترداد/الإضافة لنفس مرجع العملية، مع إعادة فحص الخصم بعد قفل المحفظة ومعالجة تعارضات التزامن. أُضيف مفتاح idempotency لعمليات إضافة رصيد المسؤول، وأُوقف منح صلاحية تنفيذ RPC الإضافة القديم غير المحمي بمرجع تكرار لدور `service_role`. يفشل الترحيل إذا اكتشف مراجع مكررة قديمة بدل حذفها أو تسويتها تلقائيًا.
- أصبحت نتائج RPC المنطقية للرصيد/بيانات اعتماد المزود تتحقق من `true` صراحةً بدل اعتبار عدم وجود خطأ كافيًا.

**الحالة:** `INTEGRATION_VERIFIED / SANDBOX_BLOCKED`. فحوص المصدر 24/24 واختبار RC432 في PostgreSQL معزول نجحا في [CI run 37874933289](https://github.com/islamnagy2022-eng/MantiqatiX/actions/runs/37874933289). ما زالت اختبارات مزود SMM الفعلية/المحاكاة السلوكية ومراجعة مصالحة الإنتاج مطلوبة. لم يتم نشر Edge Function أو تطبيق RC432 على الإنتاج.

**ERP RC434–RC438:** أصبح أمر الشراء يدعم بنودًا صريحة مع حساب إجمالي خادمي، واعتماد الطلبات مرتفعة القيمة، واعتماد تلقائي للطلبات منخفضة القيمة، وتحقق الاستلام من المنتج والكمية التراكمية وتكلفة الوحدة. أضيف RC437 لربط الاستلام ببنود الأمر ومنع استدعاء RPC الاستلام القديم مباشرة من `service_role`، وRC438 لإنشاء أمر الشراء وبنوده ذريًا عبر Edge Function موثّق، وربط RPC بهوية الممثل التي تحقق منها الخادم، وحساب الإجمالي على الخادم. أضيف اختبار تكامل PostgreSQL معزول يغطي إنشاء الأمر والتكرار، تعارض البنود ورقم الأمر، حدود الاستلام، مطابقة التكلفة، التراجع عند فشل دفتر المخزون، وعزل المستأجر. فحص القراءة فقط للإنتاج بتاريخ 2026-10-09 أظهر 0 أوامر شراء و0 استلامات و0 حركات استلام مشتريات؛ لذلك لا يوجد سجل قديم ظاهر يحتاج backfill حاليًا، لكن يجب إعادة الفحص قبل النشر. الحالة: `CI_PENDING`; لم تُطبق RC437/RC438 على الإنتاج.

## بوابة الإغلاق

لا تُحوّل بندًا إلى `RELEASE_READY` إلا بعد إرفاق:
1. Commit/ملفات التعديل.
2. نتيجة الاختبارات المحددة وروابط CI عند توفرها.
3. اختبار سلبي للصلاحيات أو حالات الفشل ذات الصلة.
4. دليل تكامل في بيئة معزولة.
5. المخاطر المتبقية والإجراء الخارجي المطلوب.

لا تُحوّل أي بند `BLOCKED_EXTERNAL` إلى مكتمل بسبب عدم توفر الصلاحية أو البيئة. تبقى بوابة الإطلاق العامة مفتوحة حتى اجتياز حواجز P0 في سجل الإنتاج.

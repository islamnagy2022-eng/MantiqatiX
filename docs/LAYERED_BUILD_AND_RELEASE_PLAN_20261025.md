# MantiqatiX — خطة البناء والإطلاق بالطبقات
تاريخ التحديث: 2026-10-25

## مبدأ العمل
نبني المنتج على طبقات رأسية مكتملة قابلة للاختبار والإطلاق، وليس على فتح كل الموديولات في وقت واحد. كل طبقة لها نطاق واضح، ومالك بيانات، واختبارات قبول، وإصدار ثابت. لا نعيد بناء ما يعمل، ولا نفتح طبقة لاحقة قبل اجتياز بوابة الطبقة الحالية. يمكن أن تعمل فرق التطوير بالتوازي، لكن النشر يظل محكومًا بالاعتماديات وبوابات الأمان.

## خريطة الطبقات

| المرحلة | الناتج القابل للاستخدام | بوابة القبول | السياسة |
|---|---|---|---|
| L0 — أساس النشر | إعداد البناء، الإعدادات، المراقبة، الرجوع للإصدار السابق | build + security checks + rollback path | لا أسرار في العميل |
| L1 — الشاشة الرئيسية | الرئيسية، التنقل، الدخول، الروابط العامة، عرض الموديولات | روابط حقيقية، موبايل، لا روابط مكسورة، smoke test | الموديولات غير المكتملة تظهر «تحت الإنشاء» |
| L2 — صفحة المشروع | صفحة مستقلة لكل نشاط/مشروع حسب الموديول والقطاع والمالك | إنشاء/عرض/تعديل ضمن نطاق المالك، رابط عام، RLS | لا خلط بين FOOD وبقية القطاعات |
| L3 — قائمة المنتجات | إضافة/تعديل/إخفاء المنتج، السعر، الصورة، التصنيف، الترتيب | عزل الملكية، تحقق المدخلات، HTTPS للصور، حدود الباقة | لا حقول غير مدعومة للقطاع |
| L4 — تفاصيل المنتج | وصف، صور إضافية، متغيرات/إضافات، توافر ومخزون عند الحاجة | تحقق schema + اختبار قطاعي + صلاحيات | المخزون لا يضاف إلى القطاعات التي لا تحتاجه |
| L5 — تفاعل العميل | واتساب/استفسار/حجز/طلب حسب الموديول | ترميز آمن، عدم كشف بيانات، إقرار واضح بحالة الطلب | لا يُدّعى أن الاستفسار طلب مؤكد |
| L6 — الطلبات والدفع | الطلبات، الدفع، webhooks، المحفظة والتسويات حيث تنطبق | idempotency، تطابق المبلغ والعملة، E2E وreconciliation | الدفع الحقيقي مغلق حتى نجاح اختبارات الدفع |
| L7 — الباقات والصلاحيات | مستويات الباقات، الميزات، حدود الاستخدام، الأدوار والصلاحيات | enforcement على الخادم وRLS/RPC، اختبارات تجاوز الحدود | إخفاء الزر وحده ليس حماية |
| L8 — التشغيل والإطلاق الموسع | تقارير، دعم، نسخ احتياطي، استعادة، مراقبة وتنبيه وتراجع | تجربة استعادة ناجحة، تنبيهات واختبار تراجع | لا اعتماد على تقرير ساكن فقط |

## أسلوب إصدار كل طبقة
1. تثبيت النطاق والاعتماديات.
2. تنفيذ التغييرات المطلوبة فقط.
3. اختبار آلي للملفات والعقود، ثم اختبارات تكامل/متصفح حسب نوع التغيير.
4. نشر معاينة أو نشر محدود للنطاق المسموح فقط.
5. smoke test بعد النشر، وتسجيل رابط التشغيل وCommit ونتيجة الاختبارات.
6. وسم الإصدار على أنه VERIFIED فقط مع دليل. غير ذلك BLOCKED أو PARTIAL.
7. عدم تنفيذ migrations الإنتاج أو الدمج التلقائي لتغييرات backend/payment لمجرد نجاح واجهة المستخدم.

## الوضع الحالي الموثق
- فرع التطوير: `feat/digital-page-self-service-20261025`.
- PR #374 ما زال draft/open وغير مدمج.
- يوجد عمل قائم على كتالوج الصفحات ذاتية الخدمة، وواجهة منيو/منتجات، وتأجيل صفحة الخدمات التسويقية.
- تمت إضافة عرض ميزات الباقات من بيانات قاعدة البيانات، لكن enforcement لكل حدود الباقة على الخادم لم يكتمل بمجرد عرض الميزات.
- لا يوجد دليل CI أخضر على أحدث commit ضمن الفحص الحالي؛ بعض jobs التي شوهدت كانت queued/cancelled.
- لم يتم تنفيذ نشر إنتاج أو ترحيلات قاعدة بيانات إنتاجية من هذا المسار.
- الحالة: **BLOCKED / NOT CERTIFIED** إلى أن تنجح بوابات الإصدار ذات الصلة.

## التنفيذ التالي
1. إغلاق L1 على نسخة محددة: تدقيق الروابط، الدخول، التنقل، responsive، وpublic smoke test.
2. إغلاق L2 للنوع الأول من الصفحات فقط، وعدم ادعاء تغطية كل الموديولات.
3. إغلاق L3 على كتالوج FOOD/المنيو أولًا، مع اختبارات ملكية وعزل.
4. بدء L4 بعد استقرار L3، ثم L5.
5. فصل L6 (الدفع والطلبات المالية) عن إطلاق الكتالوج البسيط.
6. بناء L7 كطبقة صلاحيات وentitlements مستقلة مع enforcement من قاعدة البيانات/الخادم.


## اعتماد نظام الإطلاق الطبقي — 2026-10-25

تم اعتماد الطبقات L0–L8 كطريقة العمل الإلزامية لهذا المسار. كل طبقة تُسلَّم كوحدة تشغيل قابلة للاستخدام، مع بوابة قبول، وإصدار ثابت، واختبارات مناسبة، وأدلة نشر؛ لا يعني اكتمال الواجهة اكتمال التفويض أو backend.

### سجل الطبقات الحالي
- L0 — أساس النشر: PARTIAL؛ يوجد workflow للنشر والتحقق، لكن rollback والتعافي ومراقبة الإنتاج لم تُثبت كاملة في هذه الدورة.
- L1 — الشاشة الرئيسية: IMPLEMENTED / NOT VERIFIED؛ أُضيف مدقق ثابت مستقل `scripts/validate-layer-l1-homepage.mjs` إلى CI للتحقق من أصول الصفحة وإصدارات الكاش وروابط الموديولات وحدود المعاينة. لا تُعتبر الطبقة VERIFIED حتى ينجح CI على commit الحالي ويثبت smoke test المنشور.
- L2 — صفحات المشروعات: PARTIAL؛ يوجد أساس الصفحات ذاتية الخدمة والمنيو، لكن يلزم اختبار E2E لهوية مالك ومستخدم آخر وعزل RLS قبل الاعتماد.
- L3 — المنتجات: PARTIAL؛ يوجد تحرير منتجات في كتالوج الصفحات، ويلزم اختبار CRUD وعزل الملكية وحدود الاستخدام من الخادم.
- L4 — تفاصيل المنتجات: PARTIAL؛ دعم التفاصيل يختلف حسب الموديول ولم يُعتمد كطبقة عامة.
- L5 — تفاعل العميل: PARTIAL؛ مسار واتساب متاح لبعض الكتالوجات، ولا يُعامل كطلب مؤكد أو دفع.
- L6 — الطلبات والدفع: BLOCKED للتفعيل الإنتاجي حتى اكتمال اختبارات الدفع والتسوية وwebhooks.
- L7 — الباقات والصلاحيات: PARTIAL؛ عرض مميزات الباقة لا يثبت فرض الحصص على الخادم.
- L8 — التشغيل الموسع: NOT VERIFIED؛ النسخ الاحتياطي/الاستعادة والتنبيه والتراجع تحتاج أدلة تشغيل فعلية.

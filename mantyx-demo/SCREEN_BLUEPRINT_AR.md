# Mantyx — مرجع استكمال الشاشات والبناء الناقص في MantiqatiX

**الغرض:** تحويل Mantyx من لوحة عرض عامة إلى نموذج مرجعي تفصيلي للشاشات ومسارات العمل الناقصة، بحيث يستطيع فريق MantiqatiX تنفيذها بسرعة مع الرجوع إلى مصدر الحقيقة الحالي بدل إعادة اكتشاف المتطلبات.

**الحالة:** مرجع تصميم/تدفقات قيد الاستكمال — ليس تطبيق إنتاج ولا إثباتًا بأن وظائف الخلفية موجودة.

## 1) قواعد لا يجوز تجاوزها

1. MantiqatiX هو مصدر الحقيقة للهوية، وقواعد البيانات، والصلاحيات، والأسعار، والطلبات، والدفتر المالي، وواجهات API/Edge Functions.
2. Mantyx يستخدم بيانات اصطناعية فقط، ولا يتصل بـSupabase أو بوابات الدفع أو البريد/SMS/Push أو حسابات الإعلانات.
3. لا تُنسخ بيانات إنتاج أو مفاتيح أو سجلات عملاء أو معاملات مالية إلى Mantyx.
4. كل إجراء في النموذج يجب أن يبيّن: المدخلات، التحقق، التأكيد، النجاح، الفشل، منع التكرار، سجل التدقيق، والصلاحيات المطلوبة.
5. لا تُنشأ قاعدة بيانات أو business logic ثانية لمجرد أن الشاشة تحتاج بيانات. كل شاشة تُربط لاحقًا بالعقد/المصدر المعتمد في MantiqatiX.
6. DONE لا تعني VERIFIED. لا يعلن أي تدفق مكتملًا قبل اختبار تكاملي معزول وإثبات الصلاحيات وعزل المؤسسات.
7. لا دمج ولا نشر ولا ترحيلات إنتاج ضمن هذا العمل التجريبي. نقل كل تحسين يكون عبر PR منفصل ومراجعة صريحة.

## 2) خريطة الشاشات المستهدفة

كل مساحة أدناه يجب أن تحتوي عند الحاجة على: قائمة، بحث/تصفية/ترتيب، تفاصيل سجل، إنشاء/تعديل، تأكيد الإجراء، سجل حالة/نشاط، وحالات Loading / Empty / Error / Permission denied / Retry. لا تعرض أي أرقام أو بيانات تجريبية على أنها بيانات حية.

| المساحة | الشاشات المطلوبة في Mantyx | التدفق الأساسي المطلوب تمثيله |
|---|---|---|
| نظرة عامة | KPIs، نشاط حديث، المهام، التنبيهات، روابط الوحدات | المؤشر ← التفاصيل ← مصدر الرقم |
| دليل الوحدات والشاشات | فهرس كل الوحدات، مستوى الاكتمال، الشاشات التابعة، العقد المطلوبة | اختيار الوحدة ← مراجعة الشاشات ← قائمة النواقص |
| التحكم الكامل | الأنشطة، المؤسسات، الفروع، الكتالوج، إعدادات المنصة، الاعتمادات | طلب ← مراجعة ← قرار مبرر ← تدقيق |
| القطاعات والكتالوج | القطاعات، الخدمات، التصنيفات، الأسعار المعروضة، حالة الإتاحة | قطاع ← خدمة ← مقدم خدمة ← طلب |

| المالية والمحافظ | دفتر الأستاذ، المحافظ، القيود، الدفع، الاسترداد، التسويات، المطابقة | حدث دفع موثق ← قيد ذري ← مطابقة ← تسوية |

| المخزون والمشتريات | الأصناف، المستودعات، حركات المخزون، أوامر الشراء، الاستلام، التحويل | أمر شراء ← اعتماد ← استلام موثق ← حركة مخزون |

| البقالة والسوبر ماركت | الفروع، الأصناف، التوفر، المخزون، سلة الطلب، التجهيز، التوصيل | فرع ← كتالوج/سعر معتمد ← طلب ← تجهيز ← تسليم |

## 4) المتطلبات المشتركة لكل شاشة

- **النطاق:** تحديد actor + role + tenant/business/branch/organization؛ لا يكفي إخفاء زر في الواجهة.
- **القراءة:** تحميل، نتائج فارغة، خطأ آمن، إعادة المحاولة، وترقيم/حدود للنتائج الكبيرة.
- **الكتابة:** تحقق من الحقول، منع التكرار، تأكيد الإجراءات الحساسة، معالجة التعارض، ورسالة نجاح/فشل واضحة.
- **الحالة:** سجل انتقالات موثوق، وعدم السماح بتجاوز الحالات أو تعديل الحالة الحساسة من العميل.
- **المال والأسعار:** السعر النهائي والخصومات والعمولة والعملة والـsnapshot مصدرها الخادم؛ لا تعدّل الواجهة الدفتر أو الرصيد.
- **الأمان:** اختبار IDOR وtenant isolation وتبديل العضوية والصلاحيات قبل/بعد تغير الدور.
- **الخصوصية:** أقل قدر من بيانات المستخدم، وعدم إظهار المستندات أو البيانات الطبية/الشخصية إلا للجهة المخولة.
- **الإتاحة:** لوحة مفاتيح، focus states، labels، رسائل قابلة لقارئات الشاشة، وتوافق الهاتف.
- **التشغيل:** correlation ID، قياس أخطاء دون تسريب PII/secrets، وسجل تدقيق للأفعال الحساسة.
- **الاختبارات:** unit/contract + E2E لكل دور ونطاق + حالات فشل وتكرار وتزامن، في بيئة معزولة.
- **التوثيق:** source of truth، الجداول/RPC/Edge Function، المالك، المتطلبات السابقة، اختبارات القبول، وخطة التراجع.

## 5) فجوات إطلاق معروفة يجب أن تبقى ظاهرة

وفق `docs/MASTER_PRODUCTION_TODO.md` في المصدر الأساسي، لا ينبغي تحويل البنود التالية إلى PASS بمجرد رسم الشاشات:

- مصادقة وصلاحيات متعددة المستخدمين والمؤسسات وOTP/refresh/logout وعزل tenant: **NOT VERIFIED**.
- دورة العميل ← مقدم الخدمة ← الطلب ← الحالة ← الإشعار: **NOT VERIFIED**.
- Paymob production E2E وHMAC/replay/idempotency وربط الدفع بالطلب: **WAIT**.
- Finance/Settlement E2E والقيود والعمولات والتسويات والمطابقة: **NOT VERIFIED**.
- تفعيل leaked-password protection من مالك المشروع وإعادة فحص Security Advisor: **WAIT**.
- استعادة نسخة احتياطية حقيقية، RPO/RTO، واستعادة نطاقي مؤسستين: **غير مكتملة**.
- تحليلات G11 وتضييق نطاق التقارير حسب الدور والمؤسسة وdrill-down: **PARTIAL**.
- اختبارات CRM والدعم والإشعارات وclick-through وعزل العملاء/المزودين: **NOT VERIFIED**.
- صحة كتالوج الأسعار، منع التكرار والتزامن، واختبارات الأجهزة/الاتصال المتقطع: **PARTIAL / WAIT**.

## 6) طريقة التنفيذ من Mantyx إلى MantiqatiX

لكل وحدة، أنشئ بطاقة تنفيذ تحتوي على:
1. رقم/اسم الشاشة ومعرّف المسار.
2. صور/حالات الواجهة: default, loading, empty, error, permission denied, success.
3. قائمة الحقول والتحقق وقواعد الانتقال.
4. أدوار المستخدمين والنطاقات المسموح بها.
5. مصدر البيانات المعتمد، وطريقة القراءة والكتابة المعتمدة.
6. أثر قاعدة البيانات/المهاجرات، إن وجد، مع فحص التعارض قبل التعديل.
7. اختبارات القبول والأمان والتزامن والفشل.
8. تعريف DONE وشرط VERIFIED وأدلة الاختبار.
9. قائمة الملفات التي ستتغير في MantiqatiX.
10. خطة rollback ومراجعة مستقلة.

### ترتيب التنفيذ المقترح

**P0:** العضويات والصلاحيات والنطاق → الطلبات → مقدمو الخدمة → الإشعارات → الدفع/الدفتر/التسوية → الدعم والتدقيق.

**P1:** كتالوج القطاعات والأسعار → CRM → SMM والوكالة التسويقية → المخزون/المشتريات → المحتوى والتقارير.

**P2:** مجالات التخصص (الأزياء، البقالة، المطاعم، الطب، الصيانة، MantiGO، الزواج، الوظائف، التعليم، المستعمل) وفق العقود الموجودة واحتياجات الإطلاق.

**P3:** التحليلات المتقدمة، التحسينات، والإضافات التجارية غير الضرورية للإطلاق الأساسي.

هذا ترتيب تخطيطي؛ يظل الترتيب النهائي تابعًا للاعتماديات الحقيقية في المصدر الأساسي ونتائج الاختبارات.

## 7) معيار قبول Mantyx كمرجع

- كل عنصر في دليل الوحدات يفتح شاشة ذات سياق واضح وليس جدولًا عامًا بلا معنى.
- يستطيع المراجع المرور من الوحدة إلى القائمة والتفاصيل والنموذج وسير الحالة وشرح التكامل.
- البحث والتصفية والإضافة التجريبية تعمل داخل الجلسة، دون persistence أو شبكة.
- لا توجد اتصالات أو أسرار إنتاج أو بيانات حقيقية.
- لكل شاشة وصف للعقد الخلفي والصلاحيات والاختبارات المطلوبة.
- لا تُستخدم أرقام/حالات النموذج كدليل على حالة الإنتاج.
- كل ما يُعتمد لاحقًا يُنقل في PR منفصل مع اختبار مناسب؛ Mantyx نفسه لا يُدمج في موقع الإنتاج.

**الخطوة التالية:** تحويل هذه الخريطة إلى شاشة «دليل الوحدات والشاشات» داخل Mantyx، ثم إكمال كل مجال على حدة بدءًا بالمسارات ذات الأولوية P0.
